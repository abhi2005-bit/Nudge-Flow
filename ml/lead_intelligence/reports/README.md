# Reports

Write future evaluation output here; generated files are Git-ignored. A report should identify the source dataset and its checksum, label definitions, split seed and duplicate threshold, model and preprocessing choices, and evaluation partition. Report macro-F1, each intent's precision and recall, and the confusion matrix. Choose models and any confidence/abstention rules using validation data; use test data once for final evaluation.

Never present metrics from `data/synthetic_dev.csv` as customer or real-world performance. No model results are supplied by this scaffold.
